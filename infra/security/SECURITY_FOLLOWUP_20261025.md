# 보안 후속 구현 결과

사용자가 DB 변경과 운영 가입 차단을 추가 승인했다. feature/security-ops에 다음 변경을 작성했다.

- revoked_access_tokens: 로그아웃한 JWT의 SHA-256 해시를 만료 시점까지 저장하고 보호 API마다 확인한다. 동일 토큰 401, 다른 토큰 유지. 저장 실패 시 500. 프론트는 서버 성공 후에만 로컬 토큰을 삭제한다.
- rate_limit_counters: DB 공용 고정 시간 창 카운터. /api 직접 연결 IP당 90/60초, 로그인 IP·정규화 이메일 각각 10/900초, 가입 IP당 10/900초. raw IP·이메일 대신 HMAC-SHA256 키를 저장한다. 초과 429+Retry-After, DB 장애 시 500. MySQL upsert 최초 생성 경합의 P2002에는 원자 증가를 재시도한다.
- 운영 가입 차단: NODE_ENV 또는 APP_ENV가 production이면 성인 인증 제공자 연동 전까지 사용자 생성 없이 403. 개발용 가입은 테스트 전용으로 유지한다. 실제 성인 인증은 아직 구현되지 않았다.
- Prisma 모델·migration·API 명세·ERD·환경변수 설명·운영 정리/복구 절차를 함께 갱신했다.

## 결과

Prisma Client 생성, 스키마 validate, TypeScript 빌드 PASS. 회귀 **79개 = 72 통과 / 0 실패 / 7 통합 대기**, 종료 코드 0. 저장소 오류, 위조 전달 헤더, 한도 전후, 로그아웃 토큰별 폐기·원문 미저장, 프론트 로그아웃 순서, 운영 가입 무쓰기 차단을 포함한다.

이전 개발 가입의 일괄 거부 기대는 개발용 fixture 가입 201과 별도 운영 가입 403/사용자 생성 없음 검증으로 분리했다. 운영 차단이 제공자 연동을 대체했다는 의미는 아니다.

실제 HTTP/JWT/bcrypt를 실행했지만 DB는 mock이다. 새 migration은 실제 DB에 적용하지 않았다. 테스트의 통과는 MySQL 동시성·서버 재시작 후 지속성·운영 프록시·DB 복구를 입증하지 않는다. 실제 DB 부하·격리된 복원·다중 인스턴스 시험은 [SECURITY_STORAGE_20261025.md](SECURITY_STORAGE_20261025.md)를 따른다.

소셜 수정 c1ce830의 별도 24/24 통과 결과는 유지한다. 관리자 신규 브랜치는 별도 9개 중 7 통과·2 실패다. 합산하지 않는다. 상세 담당·재현은 [ADMIN_REVIEW_20261025.md](ADMIN_REVIEW_20261025.md).

## 미완료

1. 백엔드 관리자·인프라: ADM-01 CIDR 설정 오류 fail-open, ADM-02 배지 설정 beforeValue 누락 수정.
2. 백엔드·인프라: 새 보안 테이블 실제 마이그레이션·경합/부하·인스턴스 전환·재시작 검증, 실제 프록시 접속 경계 합의. 현재 프록시 주소는 공통 한도를 공유한다.
3. 백엔드·인증 제공자: 실제 성인 인증 결과 서버 검증 및 운영 가입 재개 설계.
4. 백엔드·스토리지: 원본 비공개·수락 전후·차단 후 사진 접근, 업로드 MIME/크기/픽셀/EXIF 통합 검증.
5. 운영·인프라: 실제 백업 복구 RPO/RTO 증빙 및 폐기 목록 유실 시 JWT 키 교체 절차 실습.

전체 Phase 2 완료 판정은 보류한다. main/develop에는 직접 커밋하지 않았으며 운영 설정·DB를 변경하지 않았다.
