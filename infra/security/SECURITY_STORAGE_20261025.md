# 토큰 폐기·공용 속도 제한 운영 절차

## 적용

사용자가 DB 변경과 운영 가입 차단을 승인했다. 실제 성인 인증 제공자는 아직 미연동이다. 운영 가입 403은 취약 경로를 닫는 조치이며 실제 성인 인증 기능의 완성이 아니다.

1. 적용 전 DB 백업을 확보하고 격리 복원 환경을 준비한다.
2. backend에서 `npx prisma generate`, `npx prisma migrate deploy`, `npm run build` 순으로 실행한다. 새 테이블 적용 전에 새 서버를 시작하면 보호 API가 500으로 차단된다.
3. 모든 인스턴스가 같은 DB와 JWT_SECRET을 사용하고 시스템 시간을 동기화하는지 확인한다. 로그인 10/900초(IP·이메일 각각), 가입 10/900초(IP), /api 전체 90/60초(IP) 고정 시간 창이다. 로그인 성공도 횟수에 포함한다.
4. 현재 IP는 socket.remoteAddress 기준이다. X-Forwarded-For는 무시한다. 실제 프록시 환경에서는 프록시 주소가 공통 한도를 공유하므로 배포 전 접속 경계를 인프라 담당과 검토해야 한다.
5. 로그인→/me 200→로그아웃 200→같은 토큰 /me 401, 다른 토큰 200을 검증한다. 인스턴스를 바꾸거나 재시작한 뒤에도 동일해야 한다.
6. 운영 가입 adultVerified=true가 403이고 사용자 행이 생성되지 않는지 확인한다. 운영 판정은 NODE_ENV 또는 APP_ENV 중 하나가 production이면 적용한다.
7. 동시 최초 요청의 PK 경합, 고정 창 경계, DB 장애, DB 복구 후 남은 폐기 기록, 부하·DB 저장량을 측정한다. 코드에는 PK 충돌 시 원자 증가 재시도 경로가 있다. 실제 MySQL 동시성은 아직 미검증이다.

## 저장량 정리

아래 SQL은 운영자가 정상 시간 동기화를 확인한 뒤 제한된 배치로 실행한다. 이 작업에서 운영 DB에 실행하거나 자동화하지 않았다. 기록된 expires_at보다 5분 더 지난 행만 지워 시간 차이 여유를 둔다. 각 쿼리는 영향 행 수가 10000 미만이 될 때까지 분리 실행한다.

```sql
DELETE FROM revoked_access_tokens
WHERE expires_at < UTC_TIMESTAMP(3) - INTERVAL 5 MINUTE LIMIT 10000;
DELETE FROM rate_limit_counters
WHERE expires_at < UTC_TIMESTAMP(3) - INTERVAL 5 MINUTE LIMIT 10000;
```

폐기 목록은 해당 JWT가 만료될 때까지 유지해야 한다. 백업 복원으로 로그아웃 이후 기록이 유실되면 이전 토큰이 되살아날 수 있다. 이 경우 서비스 재개 전 JWT 키를 교체하여 모든 기존 토큰을 무효화하고 재로그인시킨다. 카운터 복원·키 교체는 제한 상태를 초기화한다.

## 배포·복구 주의

애플리케이션 DB 계정에는 두 테이블 읽기/쓰기 권한이 필요하다. 보안 테이블은 기존 백업·복원 범위에 포함한다. 로그에 토큰·IP·이메일 원문 또는 DB 오류 원문을 남기지 않는다. 서버 오류는 event/incidentId로 추적한다.

구버전 서버로 되돌리면 폐기 확인·속도 제한이 사라지므로 보안 기능을 유지하는 이전 버전으로만 롤백한다. 테이블을 삭제하거나 폐기 기록을 비우는 방식의 롤백은 사용하지 않는다. 실제 DB 연결·배포·테이블 삭제는 이번 작업에서 수행하지 않았다.
