# 백업·복구 점검 및 증빙 양식

상태: 절차 작성 완료, 실제 복구 시험 미실행. 운영 자원·권한·보관 정책이 확정된 뒤 인프라 담당과 수행한다.

## 독립적으로 수행한 로컬 사전 연습

- [x] 가상 데이터만 임시 폴더에서 AES-256-GCM으로 암호화·복원.
- [x] 복원 본문·SHA-256 및 가상 역할·정지 상태·토큰 폐기 레코드 일치.
- [x] 암호문 변조·잘림·인증 태그 오류를 복원 실패로 처리.
- [x] 암호화 키는 메모리에만 보관하고 임시 파일 정리.
- [ ] 실제 MySQL·버킷·NAS 복원, 접근 제어, 알림, RPO/RTO 측정.

실행: `node infra/security/local-backup-drill.mjs --evidence`. 증빙은 evidence/local-backup-drill.json이다. 가상 파일 연습은 실제 DB/스토리지 복구 또는 실제 RTO 측정을 대체하지 않는다. 아래 실제 복구 항목은 미실행으로 유지한다.

## 시험 전

- [ ] 담당자: 인프라(백업/복원), 백엔드(DB 정합성), 보안·운영(접근/증빙)을 기록한다.
- [ ] 대상 커밋·DB 버전·마이그레이션 상태와 백업 범위를 기록한다.
- [ ] RPO(허용 손실 시간)·RTO(허용 복구 시간)는 팀 승인 목표와 측정치를 구분한다.
- [ ] 격리된 테스트 DB·테스트 버킷·테스트 NAS 경로를 준비한다. 운영 DB 덮어쓰기·reset·실제 사진 복제는 하지 않는다.
- [ ] 가상 사용자·관계·이미지 fixture를 만들고 기준 건수와 해시를 기록한다. 시드의 공개 개발 관리자 계정은 운영에 생성하지 않는다.
- [ ] 백업 계정과 앱 계정을 분리하고 백업·다운로드 권한을 최소화한다.
- [ ] 백업 파일은 비공개·암호화·보관기한·삭제 통제를 확인한다. Git에는 백업 파일 대신 식별자와 비밀 없는 결과만 기록한다.

## DB 복원

- [ ] 일일 백업 성공 시각·최근 실패·실제 복원 가능한 시각 범위를 확인한다. HA를 백업의 대체로 간주하지 않는다.
- [ ] 백업/시점 복원으로 별도 DB를 생성한다. 운영 연결 문자열은 바꾸지 않는다.
- [ ] 현재 Phase 1 사용자·프로필·선호 조건 수와 관계·인코딩을 확인한다.
- [ ] Phase 2 구현 후 하트·요청·채팅방 참여자·메시지·차단·신고·감사 로그를 확인한다.
- [ ] 선착순 재고/지급 이력/사용 이력의 일관성과 유일성 제약을 확인한다. 복원 직후 임의로 지급 API를 재실행하지 않는다.
- [ ] 복원된 role/status/adult_verified_at가 보존되고 JWT 폐기 목록·세션 상태가 과거 상태로 돌아가는 위험을 평가한다. 필요 시 전체 세션 폐기 계획을 적용한다.
- [ ] 측정 RPO는 복구된 마지막 데이터 시각으로, 측정 RTO는 요청 접수부터 앱 확인까지 계산한다.

## 사진·NAS·운영 설정

- [ ] DB 백업에 Object Storage·NAS 파일이 포함되지 않음을 확인한다.
- [ ] 사진 버전/백업본에서 테스트 객체를 복구하고 object_key 참조·해시를 확인한다.
- [ ] 복원 후에도 원본은 비공개, 익명 읽기·목록은 거부, 수락 관계 권한은 유지된다.
- [ ] 복원으로 탈퇴 사진·개인정보가 다시 서비스에 나타나지 않도록 삭제 이력과 대조한다.
- [ ] NAS 테스트 파일을 격리 경로로 복원하고 권한·파일 해시를 확인한다.
- [ ] 서버 이미지·Init Script에는 비밀이 없고 설정은 승인된 비밀 관리 수단에서 재주입한다.
- [ ] 새 서버에서도 중앙 로그·알림·접근 제어가 동일하게 동작한다.

## 종료·실패 대응

- [ ] 백업 실패 또는 복원 실패를 시험해 담당자에게 알림이 도착하는지 확인한다.
- [ ] 결과·추가 조치·책임자·재시험 일정을 기록한다.
- [ ] 승인된 테스트 자원만 이름·절대 경로를 확인하고 정리한다. 원본 백업 보관 정책은 유지한다.
- [ ] 임시 DB·스토리지·네트워크 비용 정리 여부를 확인한다.
