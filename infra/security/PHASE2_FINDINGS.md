## 재현 방법

프로젝트 루트에서 백엔드 잠금 파일 기준 의존성을 설치한 후 다음을 실행한다.

```powershell
Push-Location backend
npm ci --ignore-scripts
npx prisma generate
npm run build
Pop-Location
node backend/node_modules/vitest/vitest.mjs run --config infra/security/vitest.config.mjs --reporter=verbose
```

테스트 서버는 `127.0.0.1`의 임의 포트를 사용한다. 테스트 키·비밀번호는 실행 때 생성하고 출력하지 않는다. DB mock은 실제 DB 대신 계정 상태와 소유권 조건을 제공한다. 속도 제한 테스트는 이 로컬 서버에만 50/100회 요청한다. 현재는 실패 항목 때문에 종료 코드 1이 정상적인 관측 결과다.

## 구현 후 재검증 상세 기준

- 관리자: 현재 역할·상태를 요청마다 확인, 권한 회수 직후 재요청, 정상 변경의 before/after·작업자·결과·요청ID 영속 기록 확인.
- 프로필: 현재 테스트는 본인 쓰기 경로에서 타인 userId 무시만 확인. 타인 공개·비공개 프로필 조회 정책과 사진 응답 필드도 별도 검증.
- 추천·하트·채팅: 타인 viewerId/roomId/requestId 변조, 미추천 대상·받은 하트 역방향 요청, 중복 수락, 제3자 수락/조회/전송 검사.
- 원본: 익명 버킷 읽기·목록·정적 파일 접근 거부, 수락 전 거부, 수락 후 두 참여자만 URL 발급. 원본 object_key는 카드 응답에서 제외.
- 차단: 양방향 추천·새 요청·메시지·사진 신규 URL 거부. 기존 메시지는 기존 참여자만 조회. 정지·탈퇴 계정의 기존 토큰도 거부.
- 이미지: `.jpg` 이름의 텍스트, MIME 위조, 손상 이미지, 10MiB 초과, 2천만 픽셀 초과, 4번째 원본, 동시 업로드 우회, EXIF GPS·원본 썸네일 검사. 처리 실패 시 원본 대체 금지.
- URL: 유효기간 60초 이하, no-store, 차단 후 신규 발급 중단. 발급된 URL의 만료 전 접근과 다운로드 회수 불가는 정책상 제한으로 기록.
- 로그: 인증 헤더·중첩 password·DB URL·스토리지 서명 쿼리·채팅 content를 합성 표식으로 검증. HTTP 응답·수집 로그·백업 로그 어디에도 원문이 없어야 함.

## 수정 범위와 합의 상태

이번 PR은 보안·운영 폴더와 체크리스트만 변경한다. 백엔드·프론트·DB·Compose는 수정하지 않았다. 위 담당 역할과 코드 수정 합의는 아직 없으며, 재현과 최소 수정 방향을 인수인계한다. 이 PR이 합쳐져도 보안 문제 해결 또는 Phase 2 출시 가능 판정을 의미하지 않는다.
