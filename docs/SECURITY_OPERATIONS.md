# 까궁 보안·운영 기준

상태: 구현 전 합의 기준. 이 문서와 환경 변수만으로 접근 제어가 적용되지는 않는다.
기준 API는 `/api/v1`이며 관리자 화면과 사용자 화면은 같은 App 서버를 사용할 수 있다.

## 1. 환경 변수·Git 관리

- `.env.example`을 로컬 `.env`로 복사하고 실제 값은 로컬 또는 배포 비밀 관리 수단에서 주입한다.
- 환경 변수 이름은 제안된 계약이다. 백엔드가 실제로 읽고 유효성 검사하도록 연결한다.
- 운영에서는 필수 비밀 값 누락, 빈 관리자 허용 목록, 잘못된 저장소 설정을 시작 시 오류로 처리한다.
- 관리자 허용 IP 목록이 비어 있으면 전체 허용하지 않는다. 신뢰할 프록시 설정도 배포 시 검증한다.
- 원본 사진은 지정된 무시 경로에만 임시 저장한다. DB 덤프는 `db-dumps/` 또는 `backups/`에 저장한다.
- 모든 이미지나 `.sql`을 일괄 무시하지 않는다. 공개 개발 자산과 DB 마이그레이션은 버전 관리한다.
- `.gitignore`는 이미 추적된 파일을 제거하지 않는다. 비밀이 커밋되면 해당 키를 폐기·재발급하고 이력을 별도 정리한다.
- 보안 파일은 역할 브랜치에서 버전 관리한다. 클라우드 설정과 실제 API 구현은 별도 검증한다.

## 2. 관리자 API 접근 규칙

대상: `/api/v1/admin` 및 하위 모든 경로·메서드. 신규 관리자 API에도 기본 적용한다.

1. HTTPS를 사용하고 관리자 전용 도메인의 진입 구간에서 허용 IP만 수신한다.
2. 같은 Load Balancer의 일반 사용자 도메인으로 관리자 API를 호출해도 우회되지 않게 도메인·경로 규칙을 적용한다. 직접 App 서버 접근도 차단한다.
3. 서버는 Bearer 토큰의 서명·만료 등 인증 정보를 검증한다. 누락·위조·만료는 `401`로 거부한다.
4. 유효한 토큰이어도 서버의 현재 계정 역할이 `ADMIN`이고 활성 계정인지 검사한다. 일반 사용자·권한 회수·정지·탈퇴는 `403`으로 거부한다.
5. 토큰의 역할 값만 믿지 않는다. DB 조회 또는 즉시 무효화 가능한 권한 캐시를 사용한다.
6. 가입·프로필 수정 요청의 `role`, `status`, `adult_verified_at`는 사용자가 변경할 수 없다. 관리자 생성은 승인된 별도 운영 절차로 제한한다.
7. IP 판별에는 실제 접속 주소 또는 신뢰하도록 지정한 Load Balancer의 정보만 사용한다. 사용자가 임의로 보낸 `X-Forwarded-For`를 신뢰하지 않는다.
8. 설정 변경은 허용 범위·자료형·적용 일자를 검증한다. 선착순 N 변경은 다음 서비스 날짜부터 적용하고 현재 재고를 다시 채우지 않는다.
9. 제재·신고 처리·설정 변경은 관리자 ID, 요청 ID, 대상, 변경 전후 값, 결과, UTC 시각을 감사 로그에 남긴다. 변경 성공 시 이력 누락이 없도록 트랜잭션 또는 내구성 있는 이벤트 기록을 사용한다.
10. 로그인 실패 반복과 관리자 요청에 속도 제한을 적용한다. 토큰·비밀번호·채팅 본문·사진 서명 URL은 로그에 남기지 않는다.

공개 카드·로그·오류 응답에 관리자용 개인정보가 섞이지 않도록 응답 필드를 명시한다.
화면 숨김, CORS, 관리자 전용 도메인만으로 서버의 권한 검사를 대체하지 않는다.

## 3. 사진 저장 경로와 공개 기준

아래 버킷명은 예시이며 실제 전역 고유 이름은 인프라 담당과 확정한다.

| 종류 | 버킷 / 객체 키 예시 | 접근 기준 |
|---|---|---|
| 실제 사진 | `kkaggung-original-private` / `originals/{opaqueUserId}/{uuid}.{ext}` | 익명 읽기·목록 조회 금지, 서버만 저장·조회 |
| AI 사진 | `kkaggung-profile-public` / `profiles/ai/{opaqueUserId}/{uuid}.webp` | 공개 카드용 최종 결과만 저장 |
| 흐림 사진 | 같은 공개용 버킷 / `profiles/blurred/{opaqueUserId}/{uuid}.webp` | 서버에서 흐림 처리한 최종 파일만 저장 |

- 버킷과 경로를 모두 분리한다. 공개용이라는 이름만으로 버킷 전체 읽기·목록 공개를 허용하지 않는다. 최종 이미지 제공에 필요한 읽기만 허용한다.
- 객체 키에 이름·이메일·생년월일·원래 파일명을 넣지 않는다. 난수 경로도 접근 권한 검사를 대체하지 않는다.
- DB에는 이미지 종류와 객체 키를 저장하고, 원본 URL을 영구 저장하지 않는다.
- 원본 업로드는 서버 또는 서버가 발급한 제한된 업로드 URL로만 수행한다. 크기·실제 파일 형식·소유권을 검사하고 메타데이터를 제거한다.
- 클라이언트가 지정한 버킷·객체 키·이미지 종류를 그대로 신뢰하지 않는다. 임시 원본도 공개 경로에 저장하지 않는다.
- 카드 응답에는 AI/흐림 이미지 필드만 포함한다. 원본 객체 키·원본 URL은 제외한다.
- 본인은 자신의 사진을 조회할 수 있다. 상대 사진은 수락된 채팅방의 두 참여자만 조회한다. 대기·거절·무시 상태나 제3자는 거부한다.
- 차단·정지·탈퇴 후 상대 원본 사진의 신규 URL 발급을 중단한다. 관리자에게 원본 전체 조회 권한을 자동 부여하지 않는다. 검수 권한은 별도 설계한다.
- 원본 임시 URL은 최대 60초 유효하며 클라이언트에 `Cache-Control: no-store`로 응답한다. 원본 객체 응답·중간 캐시도 캐시되지 않게 설정한다.
- 이미 발급한 URL은 만료까지 사용될 수 있고, 이미 내려받은 사진은 회수할 수 없다. 차단 시 즉시 다운로드 차단이 필요하면 인증 프록시 방식으로 변경한다.
- AI 변환 실패 시 별도 흐림 결과를 사용한다. 흐림 생성도 실패하면 원본을 대신 보내지 않고 처리 실패 상태를 반환한다.
- 공개 결과의 메타데이터·썸네일·정적 파일 경로에도 원본이 섞이지 않는지 검사한다.

## 4. 시간·상호작용 기준

- 서비스 하루는 한국 시간 오전 8시부터 다음 날 오전 8시 직전까지다. 오전 8시 이전은 전날 서비스 날짜에 속한다.
- 응답 시각은 UTC `Z`로 통일한다. 예: KST `2026-10-27 08:00`은 `2026-10-26T23:00:00Z`.
- 새로고침권은 다음 날 오전 8시에 만료된다. 인증 Access Token과 새로고침권은 서로 다른 개념이다.
- 채팅 요청은 현재 추천 목록의 상대 또는 받은 하트 발신자에게 허용하고 차단·제재·중복 조건을 공통 검사한다.
- 차단 후 양방향 신규 요청·메시지 전송·상대 실제 사진 조회를 차단하며 기존 메시지는 기존 참여자에 한해 조회만 허용한다.

## 5. 후속 운영 작업

- 인프라 담당: 실제 서비스 포트, ACG/NACL, VPN, 외부 API용 NAT, 관리자 진입 규칙 확정.
- 백엔드 담당: 인증·현재 권한 검사, 사진 권한 검사, 감사 로그 및 환경 변수 연결.
- 보안·운영 담당: 테스트 증빙 수집, 중앙 로그·알림, 백업 복구 시험, 자원별 비용표 작성.
- DB 백업과 별도로 Object Storage·NAS의 복구 방법을 마련한다. 이미지·Init Script에는 비밀 값을 포함하지 않는다.
