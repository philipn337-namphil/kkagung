## 확정 결정

### D-01. Object Storage 버킷은 공개/비공개 2개로 분리한다

| 버킷 | 용도 | 접근 |
|---|---|---|
| `kkagung-images-public` | AI 변환 이미지, 서버 생성 블러 이미지 | 공개 읽기 |
| `kkagung-images-private` | 업로드 원본 | 비공개. 서버만 접근, 서명 URL로만 노출 |

**이유**: 단일 버킷 + 객체별 ACL 방식은 설정 실수 하나로 원본이 노출됩니다. "채팅 수락 전 신원 비노출"은 이 서비스의 핵심 요구라 **버킷 경계로 구조적으로 보장**합니다.

**구현 지침**
- 환경변수 키: `OBJECT_STORAGE_BUCKET_PUBLIC`, `OBJECT_STORAGE_BUCKET_PRIVATE`
- 버킷명을 코드에 하드코딩하지 않습니다. 환경변수로만 읽습니다.
- 원본 `object_key`는 **어떤 API 응답에도 포함하지 않습니다.** 추천 카드 응답도 마찬가지입니다.
- 원본 서명 URL은 채팅 요청 **수락 후 두 참여자에게만** 발급합니다. 유효기간 60초 이하, `no-store`.
- 실제 NCP 버킷 생성은 Phase 3입니다. 지금은 이름 규칙만 확정이며, 로컬에서는 동일 인터페이스의 대체 구현을 써도 됩니다.

### D-02. AI 변환은 인터페이스만 정의하고 당분간 PENDING으로 흘린다

**결정**: 사진 업로드 · 원본 저장 · 블러 생성까지는 **지금 구현합니다.** AI 변환은 공급자 인터페이스만 정의하고, 실제 변환 결과는 `GenerationStatus: PENDING` 상태로 둡니다.

**이유**: AI 공급자 선정은 비용·계정 발급이 선행돼야 해서 Phase 3 사안입니다. 여기에 사진 기능 전체를 묶으면 프로필·추천 카드가 계속 `null`로 남습니다. 스키마에 `GenerationStatus` enum이 이미 있으므로 구조는 준비돼 있습니다.

**구현 지침**
- `ImageType`별 처리: 원본 = 즉시 저장, 블러 = 서버에서 생성, AI = `PENDING` 행만 생성
- 추천 카드는 **AI 이미지가 없으면 블러 이미지로 대체**해 응답합니다. 카드 사진이 `null`로 비는 상태를 없앱니다.
- 처리 실패 시 **원본으로 대체하지 않습니다.** 실패는 실패로 남기고 카드에서 제외합니다.
- AI 공급자 호출부는 교체 가능한 단일 모듈로 격리합니다.

### D-03. JWT TTL은 환경변수로 분리하고 개발 12시간 / 운영 15분으로 한다

**배경**: 보안 정책은 900초, `backend/src/auth.ts`는 `expiresIn: "12h"` 하드코딩, API 명세서는 12시간 표기 — 3군데가 어긋나 있었습니다.

**결정**
- `backend/src/config.ts`에 `jwtExpiresIn` 항목을 추가하고 `auth.ts`의 하드코딩을 제거합니다.
- 기본값: 개발 `12h`, 운영(`NODE_ENV=production`) `900s`
- 환경변수 키: `JWT_EXPIRES_IN`
- `docs/03_API_명세서.md`의 "12시간" 표기를 "환경별 설정값(개발 12h / 운영 900s)"으로 고칩니다.

**이유**: 데모 편의(12시간)와 보안 정책(15분)은 환경이 다른 문제였습니다. 값을 하나로 고르는 대신 환경으로 분리합니다.

### D-04. 보안 담당의 코드 수정 권한을 인증 관련 백엔드 파일에 한해 허용한다

**결정**: 보안·운영 담당(김서현)은 아래 파일을 **직접 수정할 수 있습니다.** PR 리뷰는 백엔드·DB 담당(박민상)이 맡습니다.

```
backend/src/config.ts
backend/src/middleware/auth.ts
backend/src/routes/auth.ts
```

**이유**: `PHASE2_FINDINGS.md`의 지적 16건 중 대부분이 이 3개 파일에 몰려 있는데, 수정 권한이 없어 전부 대기 상태였습니다. 위 파일은 백엔드의 미병합 기능 브랜치와 겹치지 않아 충돌 위험도 낮습니다.

**범위 밖 (종전대로 담당자 합의 필요)**
- 그 외 `backend/` 파일 — 백엔드·DB 담당(박민상) 영역
- `backend/prisma/` 스키마·마이그레이션 — 백엔드·DB 담당 영역
- `frontend/` — 프론트엔드 담당(이재원) 영역 (아래 참조)
