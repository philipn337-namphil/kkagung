# 08. 발표 시연 시나리오

> 무엇을 어떤 순서로 보여줄지, 그리고 그 전에 무엇을 확인해야 하는지.
> 구성과 배포는 [05](05_NCP_아키텍처.md) · [07](07_NCP_배포_절차.md) 에 있다.

## 보여주려는 한 가지

**수락 전에는 상대가 누구인지 알 수 없고, 수락하면 이름과 실제 사진이 공개된다.**

나머지(운세, 선착순 새로고침권, 관리자, Auto Scaling)는 이 이야기에 붙는 것이다.
시간이 모자라면 뒤에서부터 자른다.

---

## 시작 전에 — 하지 않으면 시연이 막히는 것

### 1. 발표장 IP 를 관리자 허용 대역에 넣는다

**이게 제일 위험하다.** `ADMIN_ALLOWED_IP_CIDRS` 에 없는 주소에서는 관리자 API 가 **전부 403** 이다.
발표장 네트워크가 사무실·집과 다르면 관리자 화면이 통째로 안 열린다.
`/health` 는 정상이고 다른 화면도 멀쩡해서, 관리자 메뉴를 누르기 전까지 모른다.

발표장에서 쓸 네트워크로 미리 접속해 주소를 확인하고 Init Script 에 더한 뒤 서버를 굴려 교체한다.
확인 방법은 아래 "시작 직전 점검" 에 있다.

> 관리자 시연을 포기한다면 이 항목은 건너뛴다. 대신 당일에 메뉴를 누르지 않는다.

### 2. `TRUST_PROXY` 가 운영값 `1` 인지 본다

부하 측정 동안 `2` 로 바꿔 두었다면 반드시 되돌린다. `2` 로 두면 클라이언트가 헤더를 위조해
속도 제한을 우회할 수 있다. 시연이 깨지지는 않지만 질문을 받으면 답하기 곤란하다.

### 3. 부하 계정을 지우고 시연 데이터를 넣는다

순서가 중요하다. 부하용 계정 2,000명이 남아 있으면 추천 카드가 `부하NNNN` 으로 채워진다.

```
5단계 측정 끝 → run-load.mjs --reset → seed-load.mjs --clean → seed-demo.mjs
```

**측정과 시연이 같은 날이면 `--reset` 을 빼면 안 된다.** 부하 계정이 그날 새로고침권
재고를 다 가져간 상태라, 빼먹으면 1번 장면이 "소진" 으로 뜬다. `--clean` 도 시연 시드도
재고를 되돌리지 않고, 관리자 화면으로도 당일 재고는 못 채운다. 명령은
[07 시연용 데이터 넣기](07_NCP_배포_절차.md) 에 있다.

넣는 방법은 [07 시연용 데이터 넣기](07_NCP_배포_절차.md) 참고.

## 리허설하면 당일 "처음 여는 장면" 을 못 본다

**오늘의 운세는 하루에 한 번만 열린다.** 같은 날 다시 들어가면 저장된 결과를 그대로 받는다.
새로고침권도 하루 한 장이고, 받은 채팅 요청은 수락하면 목록에서 사라진다.

리허설로 이것들을 한 번 쓰면 당일 본 무대에서 같은 장면이 나오지 않는다.

**되돌리는 방법은 시연 시드를 다시 돌리는 것이다.**

```bash
docker exec kkagung-api node demo/seed-demo.mjs
```

시연용 계정을 지우고 다시 만든다. 계정이 지워질 때 운세·추천·새로고침권·하트·채팅이 함께
지워지므로(모두 Cascade), 아무것도 안 열어본 상태로 돌아간다. 실제로 확인했다.

```
리허설 후   운세 1 · 추천 3 · 새로고침권 1 · 하트 3 · 대기 요청 2
다시 돌린 뒤 운세 0 · 추천 0 · 새로고침권 0 · 하트 3 · 대기 요청 2
```

**발표 직전에 한 번 더 돌린다.** 리허설을 했든 안 했든 그게 가장 확실하다.

브라우저도 정리한다. 뒤집은 타로 카드는 탭 저장소에 그날 하루 기억되므로, 새 창(또는 시크릿 창)
으로 열거나 `sessionStorage` 를 비운다. 그러지 않으면 카드가 이미 뒤집힌 채로 시작한다.

## 시작 직전 점검 — 2분

```bash
LB=http://<LB 주소>

# 1. 서비스가 떠 있나
curl -s -o /dev/null -w "%{http_code}\n" $LB/                    # 200
curl -s $LB/config.js                                            # window.API_BASE_URL = "/"

# 2. 로그인되나
curl -s -X POST $LB/api/v1/auth/login -H 'Content-Type: application/json' \
  -d '{"email":"narae@kkagung.demo","password":"kkagung123!"}'   # token 이 나와야 한다

# 3. 사진이 보이나 (403 이면 시드에 저장소 설정이 빠진 것이다)
curl -s -o /dev/null -w "%{http_code}\n" \
  https://kr.object.ncloudstorage.com/kkagung-images-public/profiles/blur/<아무 id>/demo-1.webp
```

**관리자는 발표장 네트워크에서 직접 확인한다.** 위 토큰으로:

```bash
curl -s -o /dev/null -w "%{http_code}\n" $LB/api/v1/admin/dashboard -H "Authorization: Bearer <관리자 토큰>"
```

`403` 이면 그 자리의 IP 가 허용 대역에 없는 것이다. 관리자 시연을 빼거나 IP 를 더한다.

## 시연 순서

로그인은 `narae@kkagung.demo` / `kkagung123!` 로 한다.

### 1. 오늘의 운세 — 30초

로그인하면 바로 보인다. **"매일 오전 8시에 열린다"** 는 서비스의 전제를 여기서 말한다.
같은 날 다시 들어와도 운세와 기본 추천은 바뀌지 않는다는 점을 덧붙인다.

새로고침권이 "사용 가능" 으로 떠 있다. **선착순이라 설정한 개수만 발급된다**는 것을 말해 두고
넘어간다(뒤에서 관리자 화면에서 그 개수를 보여준다).

### 2. 타로 카드 — 1분 · **여기가 핵심**

카드가 **뒷면으로 깔려 있다.** 눌러서 한 장씩 뒤집는다.

뒤집힌 카드를 가리키며 말한다.

> **이름이 없습니다.** 용산구에 사는 사슴상 28세, 키와 직업과 MBTI 까지는 보이는데
> 이 사람이 누구인지는 알 수 없습니다. 사진도 흐림 처리된 것만 나갑니다.

이게 다른 매칭 서비스와 다른 지점이다. 사진만 가리고 이름을 주면
이름·지역·나이·직업을 합쳐 사람을 찾아낼 수 있기 때문에 이름도 함께 미룬다고 설명한다.

### 3. 하트 — 20초

카드에서 하트를 누른다. 새로고침해도 유지된다는 것을 보여줘도 좋다(서버가 기억한다).

### 4. 받은 관심 — 30초

상단 "받은 알림". **하트 3개와 채팅 요청 2개**가 미리 들어와 있다.

여기서도 상대가 `마포구 · 강아지상 25` 로만 보인다. **받은 쪽에서도 똑같이 익명이다.**

### 5. 채팅 요청 수락 — 1분 · **클라이맥스**

대기 중인 요청 하나를 수락한다. 채팅방으로 들어가면 **이름과 선명한 원본 사진**이 나온다.

> 수락하는 순간 양쪽 모두에게 동시에 공개됩니다. 한쪽만 보는 상황이 생기지 않습니다.

원본 사진은 **비공개 버킷에 있고 60초짜리 서명 URL 로만 내려온다**는 점을 말한다.
주소를 복사해 둬도 1분 뒤에는 열리지 않는다.

이미 수락된 방이 하나 더 있으니(메시지 4개), 대화가 오가는 모습은 그쪽을 쓴다.

### 6. 사진 올리기 — 40초

마이페이지 → 빈 자리에 사진을 올린다. 미리 사진 파일 하나를 바탕화면에 준비해 둔다.

올리고 나면 **흐림본이 보인다.** 이게 상대에게 나가는 사진이다.
"원본 확인" 을 누르면 잠깐 선명하게 바뀐다 — 그때만 서명 URL 을 새로 받아온다.

> AI 변환은 공급자를 정하지 않아 "준비 중" 입니다. 인터페이스는 열어 뒀고,
> 그동안은 흐림본이 공개본 역할을 합니다.

구현하지 않은 것을 구현한 척하지 않는다. 물어보면 그대로 답한다.

### 7. 관리자 — 1분

`unjeong@kkagung.demo` 로 바꿔 로그인한다(또는 미리 다른 창에 띄워 둔다).

- 지표: 가입·운세 열람·하트·채팅 요청·대기 신고·새로고침 잔여
- **새로고침권 수를 바꿔 본다** — 1번에서 말한 "선착순 개수" 가 여기서 정해진다
- 사용자 하나를 "추천 제외" 로 제재해 본다. 사유가 필수고 감사 로그에 남는다

### 8. 인프라 — 1분 (시간이 되면)

콘솔을 띄워 Auto Scaling Group 을 보여준다.

- 앱 서버는 **비공인 서브넷**에 있고 LB 만 바깥을 본다
- 원본 사진은 **비공개 버킷**, 흐림본만 공개 버킷
- 부하를 올리면 CPU 기준으로 서버가 늘어난다. 늘어난 서버는 레지스트리에서 이미지를 받아
  스스로 떠서 LB 에 붙는다 — 사람 손이 들어가지 않는다
- 측정 숫자는 [07 5절](07_NCP_배포_절차.md) 에 있다

## 물어볼 만한 것

| 질문 | 답 |
|---|---|
| AI 이미지는요? | 공급자를 정하지 않아 미뤘다(D-02). 인터페이스와 상태(`PENDING`/`DONE`/`FAILED`)는 다 열려 있고, 그동안 흐림본이 공개본 역할을 한다 |
| 원본이 샐 수 있나요? | 버킷을 나눴다. 공개 버킷에는 흐림본만 올라가고, 원본 버킷은 익명 접근이 403 이다. 응답 어디에도 원본 object key 를 넣지 않는다 |
| HTTPS 아닌데요? | 도메인을 확보하지 못해 인증서를 붙일 수 없었다. 코드는 바꿀 것이 없고 도메인이 생기면 LB 에 인증서를 붙이면 된다 |
| 8시에 몰리면? | 한 대에서 측정한 값과 증설 후 값이 [07 5절](07_NCP_배포_절차.md) 에 있다. CPU 기준으로 자동 증설한다 |
| 선착순이 정확한가요? | 트랜잭션과 row lock 으로 원자적으로 차감한다. 부하 도구로 300명을 동시에 보내 설정한 100장만 발급되는 것을 확인했다 |
| 테스트는? | 152개. 실제 MySQL 과 S3 호환 저장소를 상대로 돈다. CI 에서 매번 실행한다 |

## 막혔을 때

| 증상 | 먼저 볼 것 |
|---|---|
| 화면이 안 뜬다 (503) | 서버를 굴려 교체하는 중일 수 있다. Target Group 상태를 본다 |
| 카드 사진이 빈 자리로 뜬다 | 시드에 `OBJECT_STORAGE_*` 가 빠졌다. 버킷에서 객체를 직접 열어 본다 |
| 추천에 `부하NNNN` 이 나온다 | 부하 계정을 안 지웠다. `seed-load.mjs --clean` |
| 카드 제목이 지역만 나온다 | 기능 시드 계정은 동물상이 비어 있다. 고장이 아니다 |
| 지운 객체가 403 으로 나온다 | 고장이 아니다. 목록 조회를 막아 둬서 없는 객체도 404 대신 403 이다 |
| 시드 스크립트가 모듈을 못 찾는다 | 컨테이너의 `/app/demo/` 에 넣어야 한다. 서버를 교체하면 사라지니 다시 넣는다 |
| 관리자가 403 | 발표장 IP 가 허용 대역에 없다. 관리자 시연을 건너뛴다 |
| 운세가 이미 열려 있다 | 리허설 흔적이다. 시연 시드를 다시 돌린다 |
| 새로고침권이 "소진" 이다 | 같은 날 부하 측정을 했다. `run-load.mjs --reset` 을 안 돌린 것이다 |
| 카드가 뒤집힌 채로 시작한다 | 탭 저장소에 남았다. 새 창으로 연다 |
