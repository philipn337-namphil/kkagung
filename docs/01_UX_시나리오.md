# UX 시나리오

## 공통 전제

- 모든 사용자는 성인 인증 완료 후 이용한다.
- 운세·추천 목록은 매일 오전 8시에 갱신되고 다음 날 오전 8시까지 유지된다.
- 추천 카드에는 AI 변환 이미지 또는 흐림 이미지 만 보인다. 원본 사진은 수락 전 절대 전송하지 않는다.

## U1. 가입과 프로필 설정

1. 사용자는 가입·성인 인증을 완료한다.
2. 이름(성 제외), 생년월일, 성별, 관심 성별, 지역, 키, 직업, MBTI를 입력한다.
3. 실제 사진 1~3장을 업로드한다. 원본은 비공개 저장소에 저장하고 공개용 AI 이미지 생성 작업을 시작한다.
4. 지역·나이·에겐테토·동물상·키·흡연·문신·군필·취미 선호를 입력한다. 성별·나이를 제외한 조건은 `상관없음` 가능하다.

**완료 기준:** 필수 정보·사진 처리 상태·선호 조건이 저장되어 추천 후보 생성에 사용된다.

## U2. 오전 8시 운세와 추천 카드

1. 사용자가 오전 8시 후 홈에 접속하면 서버가 오늘의 운세와 사전 생성 카드 목록을 반환한다.
2. 사용자는 운세 등급과 카드 3·5·7장을 확인한다.
3. 선착순 N명 안이면 당일 1회용 새로고침권을 지급한다.
4. 카드에서 AI·흐림 이미지, 구 단위 지역, 동물상, 나이, 성별, 키, 직업, MBTI, 배지, 추천 이유를 본다.
   **이름은 카드에 나오지 않는다.** 카드에서 상대를 가리키는 것은 지역과 동물상이다.

**완료 기준:** 같은 날 재접속해도 기본 운세·카드는 변하지 않고 새로고침권은 중복 지급되지 않는다.

## U3. 하트와 채팅 요청

1. 사용자는 오늘 추천받은 카드에 하트를 보내거나 짧은 메시지와 함께 채팅을 요청한다.
2. 하트를 받은 사용자는 받은 하트 목록에서 상대 공개 카드를 보고 역으로 채팅 요청할 수 있다.
3. 요청 수신자는 수락·거절·무시를 선택한다. 수락 시 채팅방을 하나 만든다.

**완료 기준:** 하트는 채팅방을 만들지 않으며 중복 하트·대기 중복 채팅 요청은 허용하지 않는다.

## U4. 수락 후 공개와 채팅

수락된 채팅방의 두 참여자만 **이름**, 실제 사진, 한 줄 소개, 답변, 취미, 흡연·문신·군필, 닮은 연예인을
확인하고 메시지를 주고받는다. 거절·무시·대기 상태에는 이름도 원본 사진 URL도 제공하지 않는다.

이름을 수락 이후로 미루는 이유는 카드 단계에서 상대가 누구인지 특정되지 않게 하기 위해서다.
사진만 가리고 이름을 주면, 이름과 지역·나이·직업을 합쳐 사람을 찾아낼 수 있다.

## U5. 새로고침권

당첨 사용자는 다음 날 8시 전까지 새로고침권을 사용한다. 서버는 사용·만료 여부를 검증하고 이미 본 사용자를 제외한 새 카드 묶음을 반환한다. 요청 재시도에도 한 번만 사용 처리한다.

## U6. 관리자 운영

관리자는 일별 가입·운세·하트·채팅 요청·신고 지표를 보고 사용자 제재, 인기 배지 기준, 다음 날 선착순 인원 N을 관리한다. 모든 설정·제재 변경은 감사 로그로 남긴다.

## 예외 흐름

| 상황 | 처리 |
|---|---|
| AI 이미지 생성 실패 | 서버 생성 흐림 이미지를 공개용으로 사용한다. |
| 추천 후보 부족 | 선택 조건을 완화하되 성별·나이 상호 조건, 지역, 차단, 최근 활동은 유지한다. |
| 선착순권 소진 | 기본 카드만 제공하고 미당첨을 표시한다. |
| 차단·제재 대상 | 추천·상호작용에서 제외한다. |
